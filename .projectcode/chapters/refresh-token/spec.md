# refresh-token 리프레시 토큰

종류: 기능
배울 것: 토큰 저장, 재발급 회전, 로그아웃

## 할 일
- S1 로그인하면 응답 헤더 Refresh-Token에 무작위 문자열을 담아 주고, 서버는 그 값을 14일 만료 시각과 함께 DB에 저장한다
- S2 POST /reissue가 리프레시 토큰을 받아 새 액세스 토큰(Authorization)과 새 리프레시 토큰(Refresh-Token)을 응답 헤더로 준다
- S3 재발급에 쓴 리프레시 토큰은 바로 지워져서, 같은 값으로 다시 재발급하면 401과 "다시 로그인해주세요"를 돌려준다
- S4 없거나 만료된 리프레시 토큰으로 재발급하면 401과 "다시 로그인해주세요"를 돌려준다
- S5 POST /logout이 리프레시 토큰을 받아 서버에서 지운다. 그 뒤 그 값으로 재발급하면 401이다
- S6 리프레시 토큰을 비우면 400과 "리프레시 토큰이 필요합니다"를 돌려준다
- S7 /reissue와 /logout은 액세스 토큰 없이 부를 수 있고, 브라우저 코드가 Refresh-Token 응답 헤더를 읽을 수 있다

## 요청과 응답
POST /reissue
요청: { "refreshToken": "3f1c..." }
응답 헤더: Authorization: Bearer eyJ..., Refresh-Token: 9a7b...
응답: { "status": 200, "msg": "성공", "body": null }

POST /logout
요청: { "refreshToken": "9a7b..." }
응답: { "status": 200, "msg": "성공", "body": null }

## 흐름
로그인 -> 무작위 리프레시 토큰 저장 -> 헤더로 전달
재발급: POST /reissue -> 리프레시 토큰 찾기(없으면 401) -> 만료 확인(지났으면 401) -> 쓴 토큰 지우기 -> 새 액세스 토큰과 새 리프레시 토큰 -> 헤더로 응답
로그아웃: POST /logout -> 리프레시 토큰 지우기 -> 응답

## 안 하는 것
- 리액트에서 재발급 자동으로 부르기: 안 만듦
- 이미 받은 액세스 토큰을 로그아웃으로 막기: 안 만듦
